## Resolution and preservation

The root `.gitignore` now has patterns scoped specifically to generated/local content within `media/txguard-demo/`: artwork outputs, render intermediates, WAVs, capture PNG/WebM files and raw recordings, review images and delivery MP4/WAV/PNG/ZIP files. There is no broad `media/`, `*.json`, `*.mp4` or `*.png` repository-wide ignore. Existing dependency, cache, test-output and environment-file exclusions remain in place.

**34 files are reviewed for version control:** the existing demo README, three timeline/narration/production specifications, ten scripts, tooling manifest/lockfile, two font files with both licenses, audio provenance/timing, subtitles/checksums/verification metadata and capture/review JSON evidence. The seven artwork HTML files are generated by the retained artwork script and include embedded font data; they remain local with their PNG outputs.

**172 media/output files remain on disk and are intentionally ignored.** Original recordings, final delivery archives and generated sound are preserved; ignored does not mean disposable or remotely backed up. Keep a separate private backup of the editable archive and original footage. No artifact was deleted, discarded, moved or overwritten, and no render/capture/packaging command was executed.

[The complete inventory](source-control-inventory.json) lists every original path, byte count, SHA-256 hash and disposition. All 206 hashes were checked again after the ignore changes; all matched. Only `.gitignore`, this report, that inventory and the explicit 34-file source list are intended for staging.

The standalone `deliverables/TxGuard-90s-1080p.mp4` is absent from this checkout at audit time; it was not deleted during this work. The existing editable ZIP contains the 9,995,352-byte master. Its decompressed SHA-256 is `6da81373f924bb35f152cc83e368d7d90daa83ec2e8a64b1eef7259e68423813`, matching `verification.json` and `SHA256SUMS.txt`. The archive was read in place, without extracting or replacing files.
